# 0021: デモは配布先ごとのアクセスコードで、期限付きの専用アカウントに入れる

## 状態

採用。

## 背景

公開サイトを就職活動の応募先に試してもらいたいが、未ログインのゲストはチャットしか使えず、メモ・プロジェクト・Skill・履歴などはメール認証を通らないと見られません。応募先の担当者に登録まで求めるのは現実的ではありません。

一方で、全機能を開けば LLM の費用がかかり、公開プロンプトの投稿やメール送信など他の利用者に届く操作もあります。誰でも入れる入口にはできません。

## 判断

- 管理画面で応募先ごとにアクセスコードを発行します。コードを入力すると、そのコード専用のデモ用ユーザーとしてログインします。全員で共有するパスワードやアカウントは使いません。
- デモ用ユーザーは初回の入力で作り、既定のタスクに加えてサンプルデータ（プロジェクト、チャット履歴、メモ、個人のコンテキスト、Skill）を同じトランザクションで入れます。2回目以降は、別の端末からでも同じユーザーに戻ります。
- 期間は初回の入力から 30 日です。期限を過ぎたユーザーは定期処理が削除し、それまでの間も AI 機能の入口で止めます。管理者がコードを停止したときは、その場でユーザーを削除します。
- 費用はコードごとに期間全体の上限（既定 $1.50、`DEMO_ACCESS_USAGE_LIMIT_USD`）を設け、通常ユーザーの日・週の上限と月の全体予算はそのまま適用します。
- DB にはコードの SHA-256 digest だけを保存します。コードは 59 ビット程度の乱数なので、ソルトや低速ハッシュは使いません。代わりに入力回数を接続元 IP ごとに制限します。コードを表示できるのは発行直後の1回だけです。
- 存在しない・停止済み・期限切れのコードは、同じエラー文言で拒否します。
- 利用者が自分でアカウントを削除したコードは終了扱いにし、作り直しません。作り直すと費用の上限が戻るためです。
- 機能は制限しません。公開プロンプトの投稿やメールアドレスの変更も通常どおり使えます。問題が起きたら、コードを停止すればアカウントごと削除できます。

## 影響

- デモ用ユーザーは `users` の通常の行で、`demo_access_codes.user_id` で区別します。認証・所有者確認・CSRF の経路は通常のユーザーと同じです。
- 期限切れから削除までの間（定期処理の間隔、最大約 100 分）はログインしたままですが、AI 機能は使えません。削除後は `/api/current_user` がセッションのユーザーを見つけられず、ログアウト状態に戻します。
- 削除済みのデモ用ユーザーの利用額は `api_usage_daily` に残り、月の全体予算に数えます。管理画面でコードごとの利用額を出すのは利用中のコードだけです。
- コードを停止できるのは管理画面からだけです。発行時のコードを控え忘れたときは、発行し直します。
- 実装は `services/demo_access.py`、`services/demo_sample_data.py`、`services/repositories/demo_access_repository.py`、`blueprints/auth_demo.py`、`blueprints/admin/demo_codes.py`、テストは `tests/unit/test_demo_access.py` と `tests/integration/test_demo_access.py` にあります。
