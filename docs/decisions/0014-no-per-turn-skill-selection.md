# 0014: 有効な Skill はすべて渡し、ターンごとの動的選択は採用しない

## 状態

不採用（見送り）。下の「再評価の条件」を満たしたら改めて判断します。

## 背景

利用者が有効にした Skill（個人の Skill と、既定の「生成UI」「メモ」）は、`services/user_skills.py` の `build_chat_skills_context` が1つの system メッセージにまとめ、`services/chat_context.py` が会話履歴より前の固定の指示の並びへ置きます。ここに「最新の発話に関係しそうな Skill だけをターンごとに選んで渡す」動的選択を入れる案（B）がありました。狙いは、無関係な指示を減らして入力トークンと指示の干渉を減らすことです。

検討の時点で分かっていたことは次のとおりです。

- 過去に動的選択を試した実 API 計測では、回答品質の改善を確認できませんでした（Issue #751 の記録）。
- 有効な Skill の合計は `USER_SKILLS_TOKEN_BUDGET`（3,800 トークン）に収まるよう切り詰められます。上限の範囲で全部を渡しても、1ターンの入力に占める割合は小さく、削れる量も限られます。
- Skill の文は会話履歴より前の固定部分にあり、プロンプトキャッシュの対象です（[ADR 0011](0011-prompt-cache-friendly-ordering.md)）。ターンごとに選ぶ Skill が変わると、その位置から後ろ（会話履歴を含む）のキャッシュが毎ターン外れます。
- 既定スキル「メモ」は、指示文とツールの提示が1対1で連動しています（[ADR 0013](0013-chat-writes-through-stored-approvals.md)）。Skill を ON にした利用者の通常ルームでだけツールと指示を一緒に渡し、「持っていないツールを説明する指示」も「説明のないツール」も作らない設計です。動的選択で指示だけを外すと、この連動が崩れるか、選択器がツール一覧まで変えることになり、ADR 0011 の「1ターンの間ツール一覧を変えない」とも衝突します。
- 選択器そのもの（埋め込みの近さや追加の LLM 判断）には、取りこぼしたときに Skill が黙って効かなくなるという、利用者から見えない失敗があります。

## 判断

- 動的選択は採用せず、有効な Skill はすべて、これまでどおり固定の並びで毎ターン渡します。どの Skill を使うかは、利用者の ON / OFF と、各 Skill の指示文に書く「いつ使うか」の条件で決めます。
- 既定スキルの指示とツールの提示は、今後も同じ条件で一緒に出し入れします。

## 影響

- Skill の文と会話履歴のキャッシュ命中は保たれます。入力トークンは有効な Skill の合計ぶん（上限 3,800 トークン）毎ターン含まれます。
- 新しい既定スキルや個人の Skill を足すときは、指示文の冒頭に「どの依頼で使うか」を書き、無関係な依頼では何もしないようにしてください。選択器に頼らない前提です。
- 再評価の条件: 有効な Skill の合計が予算で恒常的に切り詰められるようになった、利用者あたりの Skill 数の上限（`MAX_USER_SKILLS`）を大きく広げる、または Skill 同士の指示の干渉が計測で確認された場合。そのときは、キャッシュを壊さない置き方（変わる部分を会話履歴の後ろへ置くなど）と、既定スキルのツール連動を保つ方法を含めて新しい ADR で判断します。
