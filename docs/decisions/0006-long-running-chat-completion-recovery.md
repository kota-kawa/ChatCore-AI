# 0006: 長時間チャットの最終回答を限定継続で回復する

## 状態

採用

## 背景

複数回の Web 検索や参照検索を行うターンでは、最終回答までの所要時間と要求される出力量が増えます。従来はプロバイダが出力上限でストリームを終えても正常完了として保存していたため、途中で切れた本文が `done` になりました。また、本文送出後の一時切断は重複防止のため再試行できず、部分回答をサーバー側で保存しない経路がありました。

単純に1回の出力上限や再試行回数を増やすだけでは、思考トークンを含むモデル間の差、重複本文、ツール呼び出しの二重実行、費用上限を解決できません。

## 判断

- LLM プロバイダ層は、正常終了と出力上限終了を区別して共通の `LlmOutputLimitError` を送出する。
- ユーザーへ表示しない調査ステップは試行単位でバッファし、一時障害時は途中出力を破棄して先頭から再試行する。これによりツール呼び出しを部分ストリームから実行しない。
- 最終回答は最初のパスだけ即時配信する。出力上限または配信途中の一時障害では、表示装飾を除いた生本文を assistant 履歴として渡し、続きだけを生成する。
- 継続生成は既定3回に制限し、通常は境界の完全一致だけを除去する。継続が先頭から書き直した場合は既存本文の末尾を錨に安全に接合し、接合できない本文は重複防止のため破棄する。曖昧な類似判定で本文を削らない。
- 限定回数で完了しない場合、生成済み本文を一度だけ保存し、`incomplete` 終端イベントで部分回答と再試行可能性をクライアントへ伝える。
- SSE の待機中はイベントIDなしのコメント keepalive を使い、リプレイ履歴とアイドル判定から除外する。すべての生成・再接続経路に同じ Nginx ストリーミング設定を適用する。

## 影響

- 長い調査でも回答が出力上限をまたいで完了しやすくなり、完了不能時も部分本文を失いません。
- 継続回数分だけレイテンシとプロバイダ費用が増える可能性があります。運用側は `LLM_FINAL_ANSWER_MAX_CONTINUATIONS` で上限を調整できます。
- 継続部分は境界判定に必要な先頭だけを一時的にバッファし、それ以降は逐次表示します。先頭からの書き直しを検出したパスだけは接合まで全体を保持します。
- `incomplete` は新しい SSE 終端契約です。クライアントは本文を再保存せず、サーバー保存済みの部分回答として表示します。
