# 0015: 有効な Skill を回答前に選択する

## 状態

採用。PR #754 で本番に導入しました。当初の評価では採用を見送りましたが、導入後に差し戻した場合と比較した結果（末尾「差し戻しの評価と採用（2026-09-28）」）から、事前選択を残します。回答の途中で Skill を選び直す方式は [ADR 0014](0014-no-per-turn-skill-selection.md) のとおり引き続き採用しません。

## 背景

有効な Skill の全指示を毎ターン渡す方式では、無関係な指示が回答へ干渉する場合があります。回答の途中で Skill 本文を取得する方式は、取得の往復と判断回数が増え、過去の計測では品質改善を確認できませんでした。今回は品質改善を目的に、本体生成に入る前の一括選択を評価します。

## 判断

- 候補は利用者が ON にした個人 Skill と、現在の経路で利用可能な既定 Skill だけです。メモはログイン利用者の通常ルーム・ストリーミング経路に限定します。設定上の有効状態と、今回選ばれた状態は別に保持します。
- 会話で選ばれたモデルによる構造化判定を一度実行し、Skill の選択と生成UIのモード判定をまとめます。選択のための追加再試行や本文取得ツールは追加しません。利用制限確認の後に実行し、既存の使用量計測に含めます。
- 選択器には外部本文を前置する前の会話、プロジェクト・タスク指示、候補の完全な本文を渡します。候補の内容は実行命令ではなく判定対象のデータです。直近履歴は既存の履歴予算で制限し、要求全体が12,000トークンまたはモデルの入力予算を超えたら判定を省略します。
- 不正な判定、候補外のID、生成UIモードとの矛盾、判断不能、API失敗、入力超過では、その時点で利用可能な全候補へ戻します。本体の Skill 指示予算は従来の3,800トークンです。全候補へ戻す場合も、設定OFFや経路上利用できない Skill は戻しません。
- 選んだ Skill はターン中固定し、次の送信・再生成では再選択します。メモの指示とツール、生成UIの指示と実行契約はそれぞれ一緒に出し入れします。選ばれなかった生成UIを、利用者が明示的に拒否した状態とは扱いません。
- 選択された Skill と生成UIの契約は、履歴の後ろ、最新発話の前へ配置します。固定部分のキャッシュを維持しますが、ターン間でツール一覧が変わる影響は残るため、入力削減だけをコスト改善の証拠にはしません。

## 影響

- 通常送信と再生成が同じ選択サービスを使用します。公開API、DB、設定画面と Skill 数の上限は変わりません。
- 生成UIがOFFでも、他の候補があると事前のAI呼び出しが1回発生します。候補ゼロでは呼びません。待ち時間・総トークン・キャッシュ使用量は事前判定込みで比較します。
- 選択数、選択ID、フォールバック理由、時間、入力見積もりを構造化ログへ記録します。本文や生のプロバイダエラーを診断情報へ残しません。
- 固定入力の比較で干渉の改善と主要操作の成功率維持を確認することを採用条件とします。実APIにはばらつきがあるため、各モデルの主要操作が3回中2回以上成立することを目安にし、現行版との結果と残る失敗をPRに記録します。比較入力の作り直しで採用条件を満たしません。

## 当初の評価（見送り時点）

GPT-OSS、GPT-6 Luna、Qwenについて、通常回答、無関係な個人Skill、メモ追記、生成UI、会話の続きの5ケースを各3回、変更前後で計90ターン比較しました。Anthropicは実API比較の対象外です。LLMは実API、メモと検索結果は固定応答を使用し、DBへの書き込みは行っていません。データセットは `enabled-skill-preselection-real-api-v1`、SHA-256は `aba665245db3a40d8defdb2e00905ce863d4188c7e1c6359a97d14ecc78c1d46` です。

- Qwenの生成UIは変更後も3回中1回しか有効なArtifactにならず、主要操作が3回中2回以上成立する条件を満たしませんでした。
- Qwenでは15ターンの検索回数が5回から11回、TurnState更新不足が18回から28回へ増えました。GPT-6 Lunaでも検索回数が0回から2回へ増えています。
- GPT-OSSのメモ操作では3回ともメモSkillのみを選び、常時適用する回答スタイルを含む個人Skillを落としました。必要な個人Skillの保持に課題が残ります。
- GPT-OSSの会話継続では、既に決まった25分・20分・15分の配分を維持できた回答が3回中3回から1回へ減りました。変更後にはクイズを5分に縮めた回答と、60分という依頼に75分の表を返した回答があり、単なる表記差ではない回帰を確認しました。
- 判定を含む15ターンの料金見積もりは、GPT-OSSが約0.0382→0.0425 USD、GPT-6 Lunaが約0.0173→0.0189 USD、Qwenが約0.4296→0.4569 USDでした。アプリの料金設定とAPI使用量に基づく見積もりで、請求額の保証ではありません。
- LLM代替による同じ5ケースの比較は回答品質がすべて同等でした。不要な指示やツールの削減だけを回答品質の改善とは数えていません。

固定した語句チェックには、同義語や時間範囲による表記を失敗扱いする限界があるため、その合格数だけで採用を判断していません。上記の生成UI失敗、選択漏れ、生成テレメトリの悪化から採用を見送ります。再評価には、汎用指示と用途限定の背景が混在するSkillの扱い、および選択後の生成UIとツール判断の安定性を改善する必要があります。

## 追加改善の評価（2026-09-27）

この時点では採用見送りを維持しました。PR提出後、既知の個人 Skill 保持漏れと会話継続の配分崩れに対して、次の局所修正を固定入力で評価しました。

- Skill の先頭段落が日本語・英語の明示的な全体向け回答スタイルに一致し、話題限定の表現がない場合、選択器が Skill 全体を外しても、その段落だけを回答へ含めます。Orchid のような用途限定背景は同時に入れません。LLM 代替比較ではメモケースの有効選択を `[-1]` に固定し、この保持ガードが働くことを確認しました。実 API のメモ操作は GPT-OSS で3回とも必要な読取・追記承認を成立させました。
- 以前の利用者発話があるときだけ、選んだ案・順序・数値を維持し、固定合計の進行表と時間付き内訳の合計を確認する指示を追加しました。最終文言へ調整する前のGPT-OSS同一会話継続3回答はいずれも進行表の時間範囲を示し、選択済み案の25/20/15分と合計60分を保ちました。機械判定は時刻範囲で書かれた1件を文字列表記の違いで落としましたが、独立した意味確認では3回とも条件を満たしました。その後、日本語と英語の指示が「内訳を検算できない場合は時間付き内訳を省略する」という条件で一致するよう調整しましたが、この最終文言では実APIを再実行していません。したがって、3回の結果は以前の文言での評価であり、最終文言が時間付き内訳の有無をどう変えるかは未評価です。これは3回の限定評価であり、一般的な追質問品質の保証ではありません。
- 同一メモ入力の実 API 比較では機能条件を修正前後とも3/3満たし、修正版は個人 Skill 2200 を3/3で回答文脈に保持しました。一方、修正版の1回答に不要なJSON風の操作説明が現れました。承認処理を壊しませんでしたが、回答品質の軽い回帰として記録します。
- この継続指示は日本語と英語の簡潔なプロンプト規則です。時間制約が曖昧な履歴、非対応言語、予算による指示省略、モデルの不遵守までは解決しません。全体向けスタイル段落の検出も既知の日本語・英語の書き出しと話題限定パターンに依存します。

この改善では、Qwen の有効な生成UI Artifact 1/3、Qwen の検索回数・TurnState 更新不足、他モデルの料金・待ち時間の採用条件未達を再評価・解消していません。実検索サービスや Artifact のブラウザ描画も検証していません。追加結果だけでは採用へ変更しませんでした。

## 差し戻しの評価と採用（2026-09-28）

PR #754 はこの ADR の見送り判断と異なり main へ取り込まれました。そこで、同じデータセット（`enabled-skill-preselection-real-api-v1`、SHA-256 `aba665245db3a40d8defdb2e00905ce863d4188c7e1c6359a97d14ecc78c1d46`）で、事前選択を含む main（98664332）と、PR #754 だけを戻した版を比較しました。GPT-OSS、GPT-6 Luna、Qwen の3モデル×5ケース×3回、各側45ターンです。LLMは実API、メモと検索結果は固定応答、DBへの書き込みはありません。

- 差し戻すと、最終回答の入力トークン見積もりの中央値が3モデルとも約8,260から約12,600へ増えました（約+52%）。
- 差し戻すと、Qwen は会話継続ケースの3回すべてで依頼されていない生成UIを作り、本文が導入文だけになる回答がありました。事前選択ありでは0回です。Qwen の15ターンの料金見積もりは約0.285→0.352 USD でした。
- 差し戻すと、GPT-OSS の空回答からの回復は4回から1回へ減りました。一方で `tool_schema_retries` が0→2回、`research_failure_recoveries` が0→1回でした。
- 変わらなかった点: Qwen の有効な生成UI Artifact はどちらも3回中1回、無関係な個人 Skill の内容の混入はどちらも0回、会話継続の25分・20分・15分の配分は意味判定で3モデルとも3回中3回維持しました。TurnState 更新不足の差は1〜3回で、この標本数では因果を判断できません。

差し戻しで悪化する指標（入力トークン、Qwen の意図しない生成UI）が改善（GPT-OSS の空回答回復）を上回るため、事前選択を採用として残します。Qwen の生成UIが3回中1回しか有効にならない問題は事前選択の有無に関係なく残るため、生成UIの品質ゲート側で扱います。GPT-OSS の空回答回復の増加は、事前選択を見直すときの再評価項目として残します。
