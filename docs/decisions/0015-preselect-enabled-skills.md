# 0015: 有効な Skill を回答前に選択する

## 状態

採用見送り。[ADR 0014](0014-no-per-turn-skill-selection.md) を維持します。以下は作業ブランチで評価した方式で、本番には適用していません。

## 背景

有効な Skill の全指示を毎ターン渡す方式では、無関係な指示が回答へ干渉する場合があります。回答の途中で Skill 本文を取得する方式は、取得の往復と判断回数が増え、過去の計測では品質改善を確認できませんでした。今回は品質改善を目的に、本体生成に入る前の一括選択を評価します。

## 判断

- 候補は利用者が ON にした個人 Skill と、現在の経路で利用可能な既定 Skill だけです。メモはログイン利用者の通常ルーム・ストリーミング経路に限定します。設定上の有効状態と、今回選ばれた状態は別に保持します。
- 会話で選ばれたモデルによる構造化判定を一度実行し、Skill の選択と生成UIのモード判定をまとめます。選択のための追加再試行や本文取得ツールは追加しません。利用制限確認の後に実行し、既存の使用量計測に含めます。
- 選択器には外部本文を前置する前の会話、プロジェクト・タスク指示、候補の完全な本文を渡します。候補の内容は実行命令ではなく判定対象のデータです。直近履歴は既存の履歴予算で制限し、要求全体が12,000トークンまたはモデルの入力予算を超えたら判定を省略します。
- 不正な判定、候補外のID、生成UIモードとの矛盾、判断不能、API失敗、入力超過では、その時点で利用可能な全候補へ戻します。本体の Skill 指示予算は従来の3,800トークンです。全候補へ戻す場合も、設定OFFや経路上利用できない Skill は戻しません。
- 選んだ Skill はターン中固定し、次の送信・再生成では再選択します。メモの指示とツール、生成UIの指示と実行契約はそれぞれ一緒に出し入れします。選ばれなかった生成UIを、利用者が明示的に拒否した状態とは扱いません。
- 選択された Skill と生成UIの契約は、履歴の後ろ、最新発話の前へ配置します。固定部分のキャッシュを維持しますが、ターン間でツール一覧が変わる影響は残るため、入力削減だけをコスト改善の証拠にはしません。

## 影響

- 通常送信と再生成が同じ選択サービスを使用します。公開API、DB、設定画面と Skill 数の上限は変わりません。
- 生成UIがOFFでも、他の候補があると事前のAI呼び出しが1回発生します。候補ゼロでは呼びません。待ち時間・総トークン・キャッシュ使用量は事前判定込みで比較します。
- 選択数、選択ID、フォールバック理由、時間、入力見積もりを構造化ログへ記録します。本文や生のプロバイダエラーを診断情報へ残しません。
- 固定入力の比較で干渉の改善と主要操作の成功率維持を確認することを採用条件とします。実APIにはばらつきがあるため、各モデルの主要操作が3回中2回以上成立することを目安にし、現行版との結果と残る失敗をPRに記録します。比較入力の作り直しで採用条件を満たしません。

## 評価と見送りの理由

GPT-OSS、GPT-6 Luna、Qwenについて、通常回答、無関係な個人Skill、メモ追記、生成UI、会話の続きの5ケースを各3回、変更前後で計90ターン比較しました。Anthropicは実API比較の対象外です。LLMは実API、メモと検索結果は固定応答を使用し、DBへの書き込みは行っていません。データセットは `enabled-skill-preselection-real-api-v1`、SHA-256は `aba665245db3a40d8defdb2e00905ce863d4188c7e1c6359a97d14ecc78c1d46` です。

- Qwenの生成UIは変更後も3回中1回しか有効なArtifactにならず、主要操作が3回中2回以上成立する条件を満たしませんでした。
- Qwenでは15ターンの検索回数が5回から11回、TurnState更新不足が18回から28回へ増えました。GPT-6 Lunaでも検索回数が0回から2回へ増えています。
- GPT-OSSのメモ操作では3回ともメモSkillのみを選び、常時適用する回答スタイルを含む個人Skillを落としました。必要な個人Skillの保持に課題が残ります。
- 判定を含む15ターンの料金見積もりは、GPT-OSSが約0.0382→0.0425 USD、GPT-6 Lunaが約0.0173→0.0189 USD、Qwenが約0.4296→0.4569 USDでした。アプリの料金設定とAPI使用量に基づく見積もりで、請求額の保証ではありません。
- LLM代替による同じ5ケースの比較は回答品質がすべて同等でした。不要な指示やツールの削減だけを回答品質の改善とは数えていません。

固定した語句チェックには、同義語や時間範囲による表記を失敗扱いする限界があるため、その合格数だけで採用を判断していません。上記の生成UI失敗、選択漏れ、生成テレメトリの悪化から採用を見送ります。再評価には、汎用指示と用途限定の背景が混在するSkillの扱い、および選択後の生成UIとツール判断の安定性を改善する必要があります。
