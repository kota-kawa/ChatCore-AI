# 0018: 生成UIの中の検索画像は、署名付きの自オリジン中継だけで読み込ませる

## 状態

採用

## 背景

生成UI（[deep dive 9.6](../architecture/system_design_deep_dive.md#96-生成uiサンドボックスアーティファクト)）のサンドボックスは `img-src data: blob:` で、外部ホストの画像を読み込めません。Web 検索の画像は生成UIの外側に別の表示部品として出しており、生成UIとは同じ返信に並びません。そのため、名所や製品のように見た目が要点になる題材でも、生成UIのカードや比較表の中に写真を置けませんでした。

`img-src` を `https:` へ開ければ表示はできます。しかし生成UIの JavaScript は LLM が書いたコードで、サーバー側の危険記述チェックは境界ではありません。画像の読み込み先を外へ開けると、`new Image().src` のクエリに会話内容を載せて任意のホストへ送る経路になります。

## 判断

- モデルは画像URLを書きません。そのターンでサーバーが選定した検索画像（`services/web_search_images.py`）を、Web 検索ツールの結果に `generated_ui_images` として番号・代替テキスト・出典題名だけで渡し、モデルは `web-image:1` のような番号を HTML・CSS・JavaScript に書きます（`services/generative_ui_images.py`）。
- サーバーは、Artifact が参照した番号のうち選定済みのものにだけ、画像URLの HMAC 署名を含む中継パス `/api/chat/web-images/{署名}/{URL}` を発行し、Artifact の `images` として保存します（`services/web_search_image_proxy.py`）。`images` はスキーマ検証で署名を確かめるため、モデルが書いた `images` や署名の無いURLは保存にも表示にも進みません。
- ブラウザは iframe を組み立てるときに番号を中継URLへ置き換え、`img-src` には自オリジンの中継パスだけを、画像を参照する Artifact に限って加えます。一覧に無い番号は透明な1画素に置き換えます。
- 中継の経路はセッションを見ません。サンドボックスは不透明オリジンで Cookie を送らないためで、守るのは署名です。署名の合わないURLは取得しません。取得は URL 取得と同じ SSRF 対策（`services/url_fetcher.py`: グローバルIPのみ、DNS の固定、リダイレクトの各段の再検査）を通し、ラスタ画像（JPEG・PNG・GIF・WebP・AVIF）で 4MB 以下のものだけを返します。SVG は中継しません。
- 取得結果（失敗を含む）はサーバーのプロセス内に保持し、同じURLへの取得を成功は1日、失敗は10分に1回までに抑えます。中継パスにクエリを付けて何度開いても元サイトへは届かないため、生成された JavaScript が取得の回数や間隔で元サイトへ情報を送る経路になりません。中継が同時に実行する取得は4件までで、URL 取得と共有する同時実行枠を使い切りません。
- 画像の出典ページへのリンクは、生成UIの枠の下に親ページ側で出します。iframe の中のリンクは開けないためです。
- 対象は Web 検索でサーバーが選定した画像だけです。利用者が添付した画像は対象にしません。

## 影響

- 生成UIが外へ出せるリクエストは、署名付きの中継パスへの画像取得だけです。パスにはサーバーが選んだ画像URLしか入らないため、生成された JavaScript が実行時の値を外部ホストへ運ぶ経路にはなりません。自オリジンの他のパスは `img-src` に含めません。
- 外部サイトの画像をサーバー経由で配信します。これまでの検索画像の表示（ブラウザが元サイトから直接読み込む）とは扱いが変わるため、出典リンクを必ず併記し、応答のキャッシュは1日に留めます。画像そのものはサーバーに保存しません。
- 署名は `FASTAPI_SECRET_KEY` から導出します。鍵を替えると、保存済みの Artifact の `images` は検証で落ち、画像の位置は空になります（生成UIの他の部分は表示されます）。
- 中継は未認証で、誰でも署名付きのパスを開けます。返すのは公開 Web の画像だけです。保持はプロセスごと（合計 32MB まで、古い順に破棄）なので、ワーカーを増やすと元サイトへの取得はワーカー数ぶんまで増えます。
- 生成UIが外部へ伝えられる情報は「参照した画像を読み込んだかどうか」までです。これは検索画像パーツをブラウザが元サイトから直接読み込む従来の表示と同じ範囲です。
- 生成UIと検索画像パーツの排他（`services/message_parts_display.py`）は変えません。生成UIがあるターンでは、画像は生成UIの中にだけ出ます。
