# 0017: アカウント切り替えは待機セッションの入れ替えで行う

## 状態

採用。

## 背景

同じブラウザで複数のアカウントを使い分けるには、ログアウトしてログインし直すしかありませんでした。右上のメニューから、以前ログインしたアカウントへ再認証なしで切り替えたいという要望があります。

一方で、セッション本体は Redis に置き、Cookie には署名済みの参照 ID だけを置くという判断（[ADR 0002](0002-redis-backed-sessions.md)）と、ログアウトしたアカウントは次の利用者から使えないという性質は保つ必要があります。

## 判断

- 表示中のアカウントは従来どおり `session` Cookie が指す 1 件です。ほかにログイン中のアカウントのセッション ID を「待機セッション」として、別の署名付き HttpOnly Cookie（`session_accounts`）に最大 4 件並べます。Cookie に置くのは参照 ID だけで、ユーザー ID やプロフィールは置きません。
- 別アカウントでログイン中に認証が成功したときは、元のセッションを破棄せず待機に回し、新しいアカウントには新しいセッション ID を発行します。同じアカウント、または未ログインからの認証は従来どおり旧 ID を破棄します。
- 切り替えは表示中と待機の入れ替えです。対象は待機セッションに限り、Redis にセッションが残っていて、その `user_id` が要求と一致するときだけ成立します。
- ログアウトは表示中のアカウントだけに効きます。そのセッションを Redis から削除し、待機セッションがあれば先頭のものを表示中にします。ログアウトしたアカウントへ戻るには再認証が必要です。
- 「以前ログインしたアカウント」の表示（名前・メール・アイコン）はブラウザの localStorage に控えます。控えは表示専用で、サーバーに待機セッションが無いアカウントはログイン画面へ進めます。利用者は控えを一覧から削除できます。
- 待機セッションは使われるまで有効期限が延びません。期限が切れたものと、同じアカウントで入り直して重複したものは、待機への追加・一覧取得・切り替え・ログアウトの時点で外し、上限はその後に適用します。Redis を読めないときは一覧を変更しません。

## 影響

- 1 つのブラウザが最大 5 件の有効なセッションを持ちます。共有端末では、ログアウトしなかったアカウントに次の利用者が切り替えられます。これは 1 アカウントでログアウトしなかった場合と同じ扱いです。
- ログアウトしてもアカウントの控え（名前・メール・アイコン）は端末に残ります。チャット本文や永続キャッシュは、ログアウト・切り替え・別アカウントでのログインのいずれでも従来どおり消します。
- 開いたままの別タブは切り替え前のアカウントの画面を表示し続け、次のリクエストから切り替え後のアカウントとして扱われます。ホーム画面は持ち主の記録（`chatcore.chat.userScope`）の不一致で永続状態を破棄します。
- 追加したアカウントのセッションは空から作り、CSRF トークン以外は元のセッションから引き継ぎません。管理者ログインのフラグは、それを得たセッション（待機に回した側）にだけ残ります。
- 待機に回したセッション本体には目印（`_parked`）を付けます。待機に回る前に始まったリクエストは、楽観的排他の不一致または目印によって保存と Cookie の再発行を行わないため、表示中のアカウントを切り替え前へ戻しません。
- 実装は `services/account_sessions.py`、`services/session_middleware.py`、`services/session_scope.py`、テストは `tests/unit/test_account_sessions.py` にあります。
