# 0010: Web 出典は抜粋を保存し、本文は必要時に読む

## 状態

採用

## 背景

過去の Web 検索で見つけたページについて、後続ターンで手順・例外条件などを詳しく質問する場合があります。保存済みの抜粋だけでは必要な箇所を読めない一方、すべてのページ本文を回答と一緒に保存すると、チャットデータが肥大化します。既知の URL を読むために検索エンジンへ再問い合わせする必要もありません。

この用途では、当時のページ本文を復元することより、保存量を抑えながら必要な内容を確認できることを優先します。

## 判断

- 後続ターン用にはタイトル・URL・取得時点を表す検索日時・出典 ID・検索クエリ・結果順・引用情報と、容量を制限した抜粋を保存します。本文と画像候補を永続化する対象から外し、保存専用のシリアライザーを使います。本文の短期的な取得・処理と、後続ターン用の保存形式を分離します。
- 同じルームの現在の会話経路にある出典だけを参照候補にします。検索クエリ・日時・結果順を保った ID 群を `TurnState` へ渡し、抜粋は必要に応じて `get_evidence` で読みます。過去の抜粋全量を初期プロンプトへ毎回渡しません。
- 回答するメインモデルが単一の判断ループで参照方法を選びます。抜粋で答えられれば回答し、抜粋にない詳細が必要なら `read_web_page` で対象本文を読みます。既知のページでは情報不足、または最新性が必要な場合は検索します。詳細を抜粋から推測せず、根拠にした出典を引用します。
- 本文取得ツールは出典 ID を受け、サーバーが参照可能な URL へ解決します。既存の SSRF 対策付き取得処理を利用し、任意 URL や会話経路外の ID は受け付けません。Brave 検索の有効設定とは独立させます。
- 本文はターン内だけ保持し、範囲指定と継続位置によって分割して読めるようにします。同じ URL の成功・失敗はターン内でキャッシュし、再アクセスしません。ページが長い場合も、本文を応答から丸ごと落とすのではなく予算に収まる範囲を返します。
- 検索、根拠の読み取り、本文の外部取得には別の上限を設けます。検索上限到達だけでは読み取りを終了しません。外部取得には回数・待機時間・抽出量の上限を設け、取得日時・最終 URL・抽出の限界を返します。

この判断は [ADR 0009](0009-single-turn-state-chat-loop.md) の単一状態・単一判断ループを維持し、選択肢に既知の出典の本文読み取りを加えます。同 ADR の検索上限到達時の扱いを更新し、残っている読み取り予算を利用できるようにします。現在の実装箇所と上限値は [ARCHITECTURE.md のチャット生成と SSE](../../ARCHITECTURE.md#チャット生成と-sse) に集約します。

## 影響

- ページ本文の大きさに比例するチャット保存量の増加を避けられます。ただし、出典数とチャット履歴に応じてメタデータ・抜粋の保存量は増えます。
- 本文を読む際には Web アクセスが発生します。取得できるのはアクセス時点の内容であり、ページの変更・削除・取得制限により過去の内容を確認できない場合があります。当時の本文の復元は保証しません。
- 抽出上限や取得失敗を回答に反映し、読めなかった内容を推測で補いません。検索結果・本文は信頼できない参照データとして扱い、そこに含まれる指示を実行しません。
- 既存の evidence ID と URL を引用に再利用でき、検索結果の保存・会話経路・引用の対応を保てます。
- 旧形式の本文付きデータは互換読み取りを維持します。既存データの一括削除や DB マイグレーションは行わず、新しく保存する検索結果から軽量な形式を使います。
- 互換用の非ストリーミング経路は従来の過去検索コンテキスト注入を維持します。本文取得ツールを利用する判断ループは通常のチャット生成経路が担当します。
