# 0007: 調査ターンの回答契約を会話の末尾で渡す

## 状態

採用

## 背景

Web 検索を複数回行うターンで、最終回答が短くなる、あるいは途中で切れる問題が残っていました。[0006](0006-long-running-chat-completion-recovery.md) は出力上限で切れたストリームの回復を扱いましたが、そこで解決していない別種の劣化が併存していました。

- 調査ターンの会話履歴は末尾がツール結果 JSON になります。最終回答の指示は先頭の system ブロックへ挿入していたため、依頼文とカバレッジ要件が生成直前から数万トークン離れ、直近の文脈が根拠 JSON だけになっていました。
- ツール予算切れで調査を打ち切る経路では、モデルが調査完了ノートを書く機会を得られないまま最終回答へ進みます。ノートも下書きも渡らないため、長い調査で集めた要件がそのまま失われました。
- ステップ会計が推論ターンとツール実行で1つのカウンタを共有していたため、検索を1回増やすたびに推論ターンが1回減り、調査が深いターンほど統合に使える回数が少なくなりました。
- 出力トークン上限は全フェーズ共通で、思考トークンも同じ枠に含まれます。調査ステップと最終回答が同じ枠を取り合い、`.env.example` の既定値がコード側の既定値を下回っていたため、本文を書くフェーズが最も枯渇しやすい状態でした。
- 継続生成はパス全体をバッファしてから配信していたため、継続中はイベントが1つも流れず、停止・切断でそのパスの生成物が失われました。境界の完全一致だけを除去する重複判定は、モデルが最初から書き直した場合に本文を二重化しました。
- 入力（コンテキスト長）超過は、Claude では出力上限として継続へ回され、OpenAI 互換では汎用の `LlmProviderError` になり「内部エラー」で終わっていました。前者は継続で入力がさらに増えるため必ず再失敗します。

## 判断

- 最終回答の契約は会話の**末尾**に user ターンとして置く。system 位置には調査フェーズ終了の宣言だけを残す。契約には元の依頼文、検索プランナーが返した回答要件、調査完了ノート、モデル自身の下書きを含める。契約内へ埋め込む外部由来テキストからは制御タグを除去する。
- 研究ループとツール予算切れ時の締めステップにも、長いツール履歴の末尾へ固定の再確認 user 指示を置く。system 指示から離れた位置でも、次のツール選択または完了ノートの目的を生成直前に再提示する。
- ツール予算切れで調査を打ち切った場合は、締めのステップを1回だけ実行して調査完了ノートを必ず作る。ノートを読めなかった場合は、内部タグを除いた下書きを契約へ引き継ぎ、統合作業を捨てない。
- ステップ会計は推論ターンとツール実行を別カウンタで管理する。表示上の合計は両者の和を保つ。Web 根拠の予算は、許可されたツール実行回数すべてに満額の取り分が行き渡る大きさから算出する。予算を使い切った検索結果は `completed` ではなく `evidence_truncated` として返す。
- 出力トークン上限はフェーズ別に持つ。フェーズ別の値は `LLM_MAX_TOKENS` から派生させず、運用環境の古い値が本文を書くフェーズを道連れにしないようにする。調査を伴うターンの回答フェーズは、思考量を最小設定へ落とさない。
- 継続生成は境界の重複を除去できる分だけを貯め、それ以降は逐次配信する。未配信のバッファは生成ジョブへ渡し、停止・切断でも保存経路に載せる。継続が最初から書き直した場合は既存本文の末尾を錨として接合し、接合できないパスは破棄する。進捗ゼロのパスが出たら継続を打ち切る。
- 継続が正常終了しても新しい本文を1文字も増やさない場合は、出力上限エラーと同じ部分回答契約で `incomplete` にする。停止時にも境界除去・書き直し接合を適用し、再送された全文の二重保存を防ぐ。
- 入力超過は `LlmInputLimitError` として出力上限から分離する。回復は継続ではなく入力の圧縮とし、最終回答の送信前にトークン量を見積もって古い根拠から段階的に縮める。証拠 ID はどの段階でも残し、引用マーカーの解決を壊さない。
- 同じ入力圧縮を次の研究ステップと締めステップの送信前にも適用する。研究履歴が最終回答へ到達する前にコンテキスト上限へ達する経路を残さない。
- 1ターン分の生成テレメトリを構造化ログへ出し、「短い（不足生成）」と「切れた（打ち切り）」を運用側で切り分けられるようにする。

## 影響

- 長い調査ターンでも、依頼の各項目が回答直前の文脈に残るため、回答が短くなりにくくなります。
- 締めのステップと、調査を伴うターンの思考量引き上げにより、レイテンシとプロバイダ費用が増えます。締めのステップはツール予算切れの経路だけで走ります。
- ツール実行の上限が増えるため、Web 検索の月間クォータ消費が増える可能性があります。`CHAT_AGENT_MAX_TOOL_CALLS` で調整できます。
- 継続中も本文が流れるようになり、無音時間は重複除去の窓ぶんだけになります。
- `evidence_truncated` は Web 検索ツール結果の新しい状態値です。モデル向けの説明文を伴い、追加検索ではなく既存の根拠での回答を促します。
- 既存の `CHAT_AGENT_MAX_STEPS` を設定している環境は、推論ターンとツール実行へ半分ずつ割り当てられます。
