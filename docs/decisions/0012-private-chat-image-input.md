# 0012: チャット画像は非公開の保存先に置き、画像を読めるモデルにだけ送る

## 状態

採用

## 背景

チャットの添付は、これまでテキストだけを扱っていました。文書は本文を抜き出して `<attached_files>` として発話へ前置し、抜き出した本文を `chat_history.attached_file_contents` に保存して、後のターンでも送り直しています。画像は本文へ埋め込めません。また、選べるモデルのうち画像を読めるのは GPT-6 Luna だけです。GPT-OSS と Qwen（Groq）はテキスト専用で、画像の入った content を受け取るとリクエストが拒否されます。

プロンプト共有の画像にも保存の仕組みはありますが、公開 URL と immutable なキャッシュで配信しています（[ADR 0003](0003-prompt-attachment-storage-boundary.md)）。チャットの画像は本人の会話でしか使わないため、この仕組みをそのまま流用することはできません。

## 判断

- 画像はブラウザで長辺 2048px の WebP に縮めてから送ります。サーバーはプロンプト画像と同じ処理（`services/prompt_attachment_processing.py`）で検証し直し、表示用と縮小版の WebP だけを `CHAT_IMAGE_UPLOAD_DIR` に保存します。この処理で EXIF の向きを反映し、メタデータを除去し、アニメーションを拒否します。
- 画像 ID の先頭には、持ち主（ログイン中は利用者 ID、ゲストはセッション）の HMAC を埋め込みます。`/api/chat/images/{id}` は、閲覧者のセッションから同じ値を計算して一致したときだけ返し、一致しない場合は存在しない場合と同じ 404 にします。こうすると DB を引かずに持ち主を確認でき、DB に行を持たない一時ルームにも同じ規則が使えます。
- 履歴（`chat_history.attached_images`、一時ルームのメッセージ）に持つのは画像 ID・名前・寸法だけです。会話履歴の中では `image_inputs` という参照のまま持ち回し、`services/llm.py` のアダプタが送信直前に実データへ変換します。変換先は、Chat Completions では `image_url`、Responses API では `input_image` です。画像はキャッシュ区切りの付いたテキストより前に置きます。
- 画像を読めるモデルは `services/chat_images.py` の `IMAGE_INPUT_MODELS`（今は GPT-6 Luna だけ）で決めます。新しい画像は、それ以外のモデルでは保存する前に 400 で断ります。過去の画像がある会話を別のモデルで続ける場合は、画像を送らず、画像名の注記を本文へ足します。アダプタは、画像を読めないモデルへの `image_inputs` を必ず取り除きます。
- 予算は base64 の文字数ではなく、寸法から数えます（32px のパッチ数を 2,500 で頭打ちにし、1.2 倍）。base64 を文字として数えると、画像 1 枚で文脈窓を超えてしまうためです。
- 参照されなくなった画像は、定期処理で消します。参照中かどうかは DB と一時ストア（Redis）の両方で確認し、一時ストアを読めない回は何も消しません。一時ルームの期限は最後の操作から数えるため、ファイルの古さだけでは使用中かどうかを判断できないからです。

## 影響

- 画像を読めるモデルを増やすときは、`IMAGE_INPUT_MODELS` をバックエンド（`services/chat_images.py`）とフロント（`frontend/lib/chat_page/chat_images.ts`）の両方で更新します。
- 共有リンクとその複製には画像を含めません（共有ページには、文書を含め添付を出していません）。
- 保存先はローカルのボリュームです。複数ホストへ広げるときは、プロンプト画像と同じくオブジェクトストレージへ移す必要があります。
- 画像のトークン数は見積もりです。Luna の倍率は公開されていないため、公開されている GPT-6 系の値で多めに数えています。
