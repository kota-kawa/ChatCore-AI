# 0025: 記憶を出典つきで保存し、毎ターン使い、黙って更新し、記憶の画面だけで管理する

## 状態

採用。段階的に実装します。項目ごとの実装状況は末尾の表が正本で、未実装の項目は現在の挙動ではありません。実装が進むと [ADR 0016](0016-context-fact-confirmation.md) と [ADR 0023](0023-auto-save-extracted-memory.md) の一部（未確認の事実と自動実行の関係、上限での承認待ち）を改訂します。改訂が実際に入る PR で、両 ADR の「状態」にこの ADR への参照を足します。

## 背景

記憶（`context_facts`）は自動保存されるようになりましたが（ADR 0023）、次の問題が残っていました。

- 回答に使われるのは、入力欄の「メモ・記憶を参照」を手でオンにしたターンだけです（既定はオフ）。新しいルームの 1 ターン目は記憶を読みません。
- 抽出は 1 ターンだけを見て、既存の記憶と重複すれば捨てます。食い違う古い記憶（転職前の勤務先など）は残り続けます。照合に使った本人発話の引用は保存せず、出典は文字列 1 本だけです。
- 検索は意味検索が 0 件のときだけキーワード検索に落とす方式で、新しさや重要度は順位に効きません。会話をまたいで過去のチャットを探す仕組みはありません。
- 記憶に相当する仕組みが 3 系統あります。利用者に見える記憶のほかに、画面に出ないルーム内記憶（`memory_facts`。毎ターン別のモデルで抽出し、自動保存の設定を見ず、秘密情報の除外も無い）と、設定画面の「AI に伝えておきたい情報」（`users.llm_profile_context`）です。
- 完全に消す操作が無く（無効化だけ）、一時チャットでも記憶を読めます。
- 記憶を確かめる場所が、記憶の一覧と承認待ちの一覧に分かれています。

## 判断

### 層の構成

- **事実**（`context_facts`）を記憶の正本にします。出典は行として持ち（`context_fact_sources`。本人発話の引用、会話、発話、観測時刻）、1 つの事実に複数の出典を持てます。言及回数と最終言及日は出典から導出し、事実の行には持ちません。事実の行を更新すると `updated_at` と `revision` が進み、一覧の順序と楽観ロックに影響するためです。
- **エピソード**（会話ごとの要約）を 1 会話 1 件、バックグラウンドで作り、過去の会話の検索対象にします。対象は導入後に発話のあった通常ルームだけで、既存の会話は遡りません。
- **記憶のまとめ**は事実から作る派生物です。利用者は直接編集せず、訂正は元の事実を編集・無効化して行います。第 1 版は LLM を使わず、読み出しのたびに事実から決定的に組みます。無効化や削除が次のターンから反映されるからです。LLM で統合したまとめを足す場合は、各行に元の事実の ID を持たせ、有効でない事実を含む行を読み出し時に落とします。
- ルーム内記憶（`memory_facts`）は廃止し、事実に一本化します。「AI に伝えておきたい情報」は本人が書いた指示として残し、記憶とは統合しません。
- プロジェクトごとの記憶の分離はしません。記憶は利用者単位です。

### 書き込み

- 抽出の基準（プロンプト、しきい値、モデル）は ADR 0023 のまま使います。
- 抽出を通った候補のうち、BM25 の重複判定で落ちなかった候補と、BM25 の最良一致が有効な事実だった候補を、既存の事実と照合します。BM25 は語の重なりで重複とみなすため、題名や文型が近い食い違い（「東京に住んでいる」と「大阪に住んでいる」）や、別の好みの追加も重複になり、そのまま再言及として吸収すると置き換えも追加も起きません。そこで有効な事実との一致は、すぐ再言及にせず、その事実を近い事実として照合へ回します。近い事実は、BM25 で一致した有効な事実（埋め込みの有無や距離に関係なく必ず入れる）と、候補の埋め込みで意味が近い事実（有効な事実と、本人が無効化した事実）を合わせて最大 5 件で、1 件でもあるときだけ GPT-6 Luna（抽出と同じモデル）に追加・更新・再言及のどれかを判定させます。BM25 の最良一致が、本人が無効化した事実・却下済みの候補・同じバッチの別の候補のときは、従来どおり何も保存しません。判定が無いとき（近い事実が無い、LLM の呼び出しや応答の検証が失敗した、その候補の判定が無い）は、照合の導入前の挙動に倒します。つまり、BM25 で有効な事実に一致していた候補は再言及（出典を足す）、それ以外は新しい事実として保存します。更新では新しい事実を保存し、古い事実は消さずに無効化して新しい事実への参照（`superseded_by_fact_id`）を持たせます。再言及では既存の事実に出典を足します。判定は文面を作り直さず、新しい事実の文面は抽出が出したままです。
- 判定の適用はコードの規則で行い、誤った更新が本人の正しい記憶を黙って無効化しないよう、迷う側は追加に倒します。応答は厳格に検証し、対象は候補ごとに渡した一覧にある事実だけを受け付けます。更新は対象が有効な事実のときだけ有効で、本人が無効化した事実が対象なら追加にします（本人が消した内容を新しい内容で置き換えることはできません）。1 つの対象を同じバッチの複数の候補が更新しようとしたら、先頭の 1 件だけを更新にして残りは追加にします。同じバッチで更新によって置き換えられる事実への言い換えは、置き換えられる事実に出典を足さず、何も保存しません。本人が無効化した事実の言い換えは何も保存せず（再び覚えない）、有効な事実の言い換えは出典だけを足します。保存では、対象が判定の時点の `revision` のままの有効な事実であることを確かめて無効化し、変わっていれば置き換えず追加として保存します。ロックの中で BM25 をもう一度見て、有効な事実への一致が事前の照合と同じ事実のときだけ事前の判定を使い、食い違うとき（事前は一致していたが一致しない、一致しなかったが一致した、別の事実に一致した）は判定を捨てて従来の挙動にします。BM25 は最良一致を 1 件しか返さないため、有効な事実 A に一致した候補が、本人が無効化した事実や却下済みの候補とも重複していることがあります。このとき新しい事実になる結果（追加、置き換え、置き換えできず追加に倒れる場合を含む）は、ロックの中で本人が無効化した事実（理由 `user` か未記録）と却下済みの候補だけを対象にした BM25 をもう一度かけて確かめ、重複していれば新しい事実を作らず、A への再言及（出典を足す。A が変わっていれば何も足さない）にします。本人が消した内容・却下した内容が、有効な記憶に隠れて再び保存されないようにするためです。比較対象の事実の読み取りは重複判定と共有するので、読み取りは増えません。置き換え（`superseded`）・上限（`capacity`）で無効化した事実には働かないので、本人が元の内容に戻せます。置き換えは有効件数を変えないので、上限での入れ替えは起こしません。
- `status` の値は増やしません（`active`／`deprecated` のまま）。置き換えで無効化した事実は、無効化の理由と置き換え先の参照で区別します。値を増やすと、切り替え中に動く旧バージョンのコードが応答の検証で失敗するためです。
- 「再び覚えない」対象にするのは、利用者が自分で無効化した事実だけです。置き換えで無効化した内容に本人が戻した場合（東京→大阪→東京）は保存します。
- 保存と同じく（ADR 0023）、更新もチャットでは知らせません。置き換えで無効化した古い事実は記憶の画面に履歴として残り、そこから元に戻せます（新しい事実を無効化して古い事実を復元）。
- 承認待ちの候補は廃止します。有効な事実が上限に達したら、自動保存されたまま一度も手を入れていない事実のうち、最後に話題に出たのが古く重要度の低いものを自動で無効化し、新しい事実を入れます。本人が書いた事実と、編集・復元・重要度の変更をした事実は対象にしません。上限で無効化した内容は「再び覚えない」対象にせず、また話題に出れば保存します。すでに溜まっている承認待ちの候補は、同じ抽出基準を通ったものなので、有効件数に空きがある分だけ事実へ移します。空きが無く移せなかった候補は読まれないまま残り、候補のテーブルを削除するときに一緒に消します。
- 経過日数だけを理由にした自動失効はしません（ADR 0016 を維持）。自動で無効化するのは、置き換えと上限での入れ替えだけです。
- 利用者単位の advisory lock と DB のトランザクションは、埋め込みの生成と LLM の呼び出しをまたいで持ちません。近い事実を読む（短い読み取り）、ロックの外で埋め込みと判定をする、ロックの中で対象の状態を確かめ直して適用する、の順にします。照合で作った候補の埋め込みは保存にそのまま使い、同じ文面をもう一度生成しません。

### 読み出し

- ログイン中の通常ルームでは、記憶のまとめを毎ターン文脈に入れます。細部と過去の会話は、モデルが必要なときに検索ツールで引きます。事前の検索はしません。
- 記憶の利用は設定で丸ごとオフにできます（自動で記憶する設定とは別）。一時チャットとゲストでは読み書きしません。
- 入力欄の参照トグルはメモ専用にします。

### 信頼の分け方（ADR 0016・0023 の改訂）

ADR 0016 は「未確認の事実を読んだターンは、書き込みツールの『常に承認』を自動実行しない」と定め、ADR 0023 は自動保存した事実を未確認にしてこの抑止を保ちました。記憶を毎ターン使うと、この抑止が毎ターン働き、「常に承認」が実質使えなくなります。そこで、抑止の条件を確認の有無から出所へ改めます。

- **本人由来**: 本人が確認した事実（`last_confirmed_at` が非 NULL）と、チャットから抽出した事実（`source_kind` が `chat`）。抽出は本人の発話そのものからの引用をコードで照合して通ったものだけを保存します。毎ターン入れるまとめは本人由来の事実だけで組み、これを読んでも自動実行は止めません。
- **本人由来でない**: MCP と取り込みで入り、本人が確認していない事実。検索で読んだターンは、従来どおり自動実行を止めます。
- MCP が事実の本文を書き換えたら、出所を `mcp` に変え、出典を外します。チャット由来のまま外部クライアントが内容を差し替える経路を塞ぐためです。
- 保存する引用も秘密情報の検査対象にします。

本人の発話に貼り付けた文章の中の指示が、記憶として残る余地はあります。抽出の規則（貼り付けた内容や一度きりの依頼を記憶にしない）と、記憶の画面での確認と無効化で抑えます。チャットで知らせない分、利用者が誤った記憶に気づく機会は記憶の画面に限られます。この余地は、いま送っている発話そのものが持つ信頼の範囲を、時間をまたいで持ち越すものです。

### 整理（バックグラウンド）

- エピソードの生成などの整理は、リクエストの外で動く専用のタスクが行います。排他は DB のリースで取り、ワーカーが複数あっても、blue/green で 2 つの版が同時に動いても、同じ利用者を二重に処理しません。
- LLM の費用は利用者本人の使用量として計上し、上限に達した利用者の分は見送ります。

### 利用者の制御

- 記憶の確認・編集・無効化・元に戻す操作・削除は、記憶の画面に集約します。チャットには保存や更新の通知を出さず、承認待ちの一覧も置きません。
- 無効化（再び覚えない）と完全削除（文面ごと消す）を区別します。完全削除と「すべて削除」を足します。
- 「確認済みにする」だけの操作は設けません。本人が編集した事実は確認済みになる、という ADR 0016 の規則をそのまま使います。
- 機微な内容（健康、信条、政治的な意見、性的指向、犯罪歴、詳細な金銭の状況）は、本人が明示的に頼んだときだけ記憶します。

## 退けた案

- **参照トグルのまま検索の質だけ上げる**: 記憶が効く場面が増えません。
- **過去のメッセージを 1 件ずつ埋め込んで検索する**: 埋め込みの費用と保存量が発話数に比例し、ルームやメッセージを消したときの整合も重くなります。会話ごとの要約で足りない場面が確認できてから検討します。
- **まとめを LLM で作って保存し、整理のときだけ更新する（第 1 版として）**: 無効化・削除した内容が次の整理まで文脈に残ります。要約を重ねるうちに意味がずれる問題もあります。
- **食い違いは本人に確認してから置き換える**: 確認されなければ古い記憶が残ります。黙って置き換え、記憶の画面から戻せる方式にします。
- **更新のたびにチャットで知らせる**: 保存について ADR 0023 が退けたのと同じ理由です。毎回の表示が利用者の負荷になるため、管理を記憶の画面に一本化します。
- **上限に達したら承認待ちに入れる／新しい記憶を保存しない**: 前者は一覧が 2 つになり、後者は上限に達した利用者の記憶が育たなくなります。
- **まとめに未確認が 1 件でも含まれる間は自動実行しない**: 最も安全ですが、確認操作をしない利用者は「常に承認」が使えなくなります。
- **確認済みの事実だけでまとめを作る**: 規則を変えずに済みますが、確認しない限りまとめが育ちません。
- **`memory_facts` の内容を事実へ移す**: 逐語引用の照合も秘密情報の除外も通っていないため、移しません。

## 影響

- 抽出に加えて、近い事実があった候補だけ照合の LLM 呼び出しが増えます。既存の記憶と言い回しが近い内容を話したターンも、BM25 で有効な記憶と重複とみなされるので、LLM 呼び出し（GPT-6 Luna）が 1 回走ります（候補の埋め込みの生成は、照合の対象の候補ごとに増えます）。どちらの費用も、抽出と同じく利用者本人の使用量として計上します。ルーム内記憶の抽出（毎ターン 1 回）は無くなります。近さは埋め込みの距離で測るため、埋め込みがまだ無い事実（生成待ち）は比較されず、その間に言い換えや食い違いが来ると従来どおり追加になります。
- 記憶のまとめは履歴より前の固定側に置きます。変わるのは事実が変わったターンの次からで、毎ターン抽出していたルーム内記憶よりプロンプトキャッシュが外れる頻度は下がります（[ADR 0011](0011-prompt-cache-friendly-ordering.md)）。
- ルーム内記憶を止めると、同じルームの中で古い発話の内容を保つのは会話の要約（`chat_room_summaries`）と直近の履歴になります。
- 出典の引用はルームの削除とアカウントの削除で消えます。信頼の判定は出典の行の有無に依存させません。
- 回答の実行記録に他のルームの情報（タイトルやリンク）を載せる場合、共有リンクとルームの複製では落とします。
- エクスポート形式は変えず、出典と置き換えの関係は書き出しません。
