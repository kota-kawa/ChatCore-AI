# UI の実描画確認

合格条件・起動方法・既知の落とし穴は `docs/knowledge/frontend_visual_verification.md` が正本です。最初に読み、この手順と食い違ったら文書に従ってください。

## 手順
1. 対象を決める: 変更した画面と操作状態（ホバー、開いたメニュー、入力中など）を列挙する。ビューポートは PC 幅とスマホ幅（例: 390×740）、テーマは `data-theme` のライトとダーク。
2. 変更前（Before）を撮る: 変更を入れる前の状態で起動し、決めた組み合わせをすべて撮影する。実装後に撮る場合は、自分の変更だけを `git stash` で退避するか、`main` の別ツリーで撮る。ほかの人の未コミット変更は戻さない。
3. 変更後（After）を同じ条件で撮る: 画面・ビューポート・テーマ・操作状態・待ち方を Before と揃える。
4. 数値で確かめる: 変更で狙った要素の `getComputedStyle` と `getBoundingClientRect` を採取し、意図した値になっているかを確認する。スクリーンショットの見た目だけで判断しない。
5. 無変化を検出する: Before と After の画像のハッシュを比べ、同一なら変更が効いていない可能性を疑う。
6. 目視する: 取得した画像を実際に開き、レイアウト崩れ、文字切れ、重なり、余白、テーマ間の差異がないかを確認する。
7. 保存する: PR に載せる画像を `assets/images/` に置く。名前は既存の画像（`terms_page_desktop_light.png` など）に合わせて画面・状態・テーマを含め、Before／After が名前で分かるようにする。
8. 後片付け: 検証用の一時ページ（`frontend/pages/__ui_probe.tsx` など）と自分が起動した dev サーバーを消す。一時ページは PR に含めない。

## PR 本文に書くこと
- 確認した画面、ビューポート、テーマ、操作状態
- 実測した値（例: `position: sticky`、`top: 0px`、高さ 44px）
- Before／After の画像を同じ条件ごとに並べた表
